CvarcLogger Changelog
======================
One entry per published version. Add a new entry here every time AppVersion.Current is bumped for a
build meant to reach the user (see AppVersion.cs) -- before running publish.ps1.

Versions before 1.17 predate this changelog and are not documented here.

2.03
----
- SKCC # field now resolves live against a local, downloadable SKCC member roster: type a member's
  number and their callsign/name/location shows underneath, confirming you copied it right during the
  exchange. "Update SKCC Award Lists" refreshes the offline roster (skcc-ref.db) from skccgroup.com.
- New "SKCC" tab in Awards Progress, tracking Centurion (100 unique members), Tribune (50 members already
  Centurion+ at contact time), and Senator (200 members already Tribune+ at contact time, after your own
  running count first reaches 400 qualifying Tribune contacts) -- computed live from CW QSOs with an
  SKCC # logged, cross-referenced against the official Centurion/Tribune/Senator award-date lists. A
  best-effort estimate, not the official submission tool -- the app can't verify manual-key usage, which
  SKCC's own rules require.
- Log grid: row/log number is now its own sortable, draggable "#" column instead of static row-header
  text -- click its header to sort by it like any other column.
- Log grid: RST, QSL, and LoTW columns can now be sorted by clicking their headers (previously had no
  effect since those columns combine two fields and WPF couldn't infer a sort key on its own).
- Log grid: the top-left corner control is now a real select-all/clear-all toggle -- first click selects
  every row (handy for bulk-deleting a recurring event's daily log), second click clears the selection.
- New "Dupe Check" checkbox next to Callsign: when checked, mirrors what you type live into the log
  grid's search box so a duplicate contact turns up as you type, not after you've already logged it.
- New "Lock Fields" checkbox on the entry form title bar (per Log Mode): prevents accidentally dragging a
  field out of place while filling out the form.
- Manual: replaced every "Elecraft K4" reference for the Internet Control (CAT) feature with generic
  "internet TCP/IP capable radio(s)" wording; Appendix A's Version History table narrowed its Version
  column so Highlights has more room, shortening the table; Introduction and Quick Start sections
  rewritten to be more detailed and reader-friendly.

2.02
----
- Net roll-call markers: a checkbox on every log row (before the row number) lets a net controller track which stations have already been called on for their statement. Clear Net Markers resets everything for the next net. Session-only -- not saved to the database or ADIF.
- Sidebar rebuilt around toggle tabs: Normal/Contest and SOTA/POTA now share one button each -- click to switch to it, click again while active to flip between its two modes. Two new fully customizable tabs added (Undef-1/Undef-2, Undef-3/Undef-4, backed by 3 new QsoEntryMode values), renameable and configurable in the Columns/Tabs window exactly like every other mode.
- "Columns" renamed to "Columns/Tabs" throughout (sidebar, ribbon, and the picker window itself).
- Rename Tab dialog now sizes itself to its content (SizeToContent) so its Save/Cancel buttons can never get clipped by a fixed window height.
- Sidebar toggle tab labels now update live when a mode is renamed via Columns/Tabs (previously showed static "X/Y" text regardless of renames).
- User manual: full accuracy pass -- rewrote the Log Modes section to walk through the toggle-tab mechanic, added a Net Roll-Call Markers section, updated every Columns/Tabs, Delete button, and Enter-key reference to match current behavior.

1.46
----
- Fixed a crash seeding the DXCC entity table on a brand-new database ("no such column" / entity-code
  identity-conflict errors during first launch or a fresh install). Root cause: the DXCC entity code is
  a natural, app-assigned ID, but EF Core's default convention treated the placeholder "None" entity's
  code (0) as unassigned and let SQLite auto-generate a replacement, which collided with another real
  entity's code in the same batch. The entity code column is now explicitly marked as never
  database-generated.

1.42
----
- Fixed a serious bug where editing a QSO and saving could change its recorded date/time. The Edit QSO
  window was recomputing the UTC time using a zero UTC offset before the QSO's real offset had loaded,
  which shifted the saved time (and shifted it further on each subsequent edit). Times now stay exactly
  as recorded unless you deliberately change them. Note: any QSO edited and saved on an earlier version
  may already have a shifted time; check it against a backup if needed.
- Log grid: the Name and Comment columns are now left-aligned instead of centered, which reads better

- Edit QSO window: pressing Return now saves the QSO, matching the Log QSO / Return behavior on the main

1.41
----

- QSO Entry form: added a "Clear Database" button next to Log QSO that deletes every QSO from the

  existing Hamlib/rigctld serial radios. Configure it under Tools > CAT Control: host/IP, port, and an

- CAT Control window: the two separate enable checkboxes were replaced with a single "CAT Source"

- Columns picker: added "All" and "None" buttons to show or hide every toggleable column at once.
- Renamed the entry form's "Connect CAT" button to "Connect the CAT".
- Installer: when an existing CVARC Logger is found, it now asks whether to Update (keep your log,
  settings, and profiles) or do a Fresh install (start with clean settings). Fresh never erases your log

1.35
----
- WSJT-X/GridTracker2-relayed QSOs now run the same online callsign lookup the manual entry form uses
  before they're added to the log, backfilling Name, Grid Square, Country, State, County, City, ARRL
  Section, and CQ/ITU Zone. Only fills fields WSJT-X left blank -- never overwrites data WSJT-X already
  supplied (e.g. the grid square from the actual over-the-air exchange) with a possibly-stale lookup
  value. Best-effort: a lookup miss never blocks logging the QSO.
- Log grid row numbers now count chronologically -- the oldest QSO is always 1, the most recently logged
  QSO always has the highest number -- regardless of how the grid is currently sorted or filtered. (The
  row numbers previously just reflected the row's on-screen position, so they went backwards from the
  grid's default newest-first display and changed unpredictably when sorting or searching.)
- CAT: TX Power (W) now auto-fills live from the connected radio, alongside the existing
  Frequency/Band/Mode auto-fill. Settings > Radio Control gained a "Max Power (W)" field per radio slot
  -- CAT reports power as a 0.0-1.0 fraction of a rig's own max capability, not real watts, so this is
  what turns that fraction into an estimated wattage. Defaults to 100W per radio; adjust it if the
  displayed TX Power doesn't match your radio's own power readout (see the User Manual for how to
  calibrate it against a real reading).
- The entry form's CAT icon now swaps to a second image while CAT is connected, matching the existing
  "Connect CAT"/"Disconnect CAT" button state.
- publish.ps1: the published executable is no longer renamed with the version number -- it stays plain
  CvarcLogger.exe. The version number still appears everywhere else it already did (window title,
  CHANGELOG.txt, the manual, and the zip filename).

1.34
----
- WSJT-X log receiving now expects WSJT-X's data relayed through GridTracker2 rather than direct from
  WSJT-X: WSJT-X broadcasts to GridTracker2 (its own default port, 2237) as usual, and GridTracker2's
  "Forward UDP messages" setting (General tab) relays the same message on to CVARC Logger on port 2238.
  This sidesteps a real-world conflict discovered this release -- GridTracker2 commonly already occupies
  WSJT-X's own broadcast port directly, so CVARC Logger listening there too meant only one of the two
  programs would ever actually receive a packet (Windows delivers a shared UDP port's traffic to just one
  bound listener, not both), with no error or warning on either side to explain why nothing was being
  logged. Confirmed working end-to-end with real WSJT-X traffic.
- GridTracker2's outbound broadcast port (for CVARC Logger's own logged/edited QSOs) changed to 2240 by
  default, matching GridTracker2's "Receive ADIF UDP (Broadcasts for Logging)" setting (General tab)
  rather than its generic default listener, which is already spoken for by the WSJT-X relay above.
- Settings: the GridTracker2 checkbox is now labeled "Enable outbound log Broadcast to GridTracker2" for
  clarity, distinguishing it from the separate inbound "Enable WSJT-X log receiving" checkbox.

  - Fixed field-length encoding (was counting .NET characters, spec requires UTF-8 bytes) -- matters
    for any accented/international name. Confirmed and fixed real corruption in an actual QRZ Logbook
    export, including a defensive recovery for a field whose own declared length doesn't land on the
    next real tag.
  - QSL_SENT and QSL_RCVD now use their correct, distinct ADIF enumerations (Queued is Sent-only,
    Verified is Rcvd-only -- previously shared one mapping that could write an invalid token).
  - Band "1.2M" corrected to "1.25M" (ADIF's actual token for 222-225 MHz), including CAT auto-fill.
  - Removed the synthetic "DATA" Mode bucket -- Mode/Sub-Mode now directly use ADIF's real vocabulary
    (FT8, FT4, RTTY, PSK+PSK31, DIGITALVOICE+DMR/DSTAR). Existing QSOs still using the old scheme are
    migrated automatically on next launch.
